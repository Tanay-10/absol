Design — Mock Data & API

How the 5 sample events are generated and how trajectory surfaces in the API response.

Mock Events — 5 samples with realistic trajectories

Event Type Path character Interval Waypoints State fields
🌀 Hurricane Mara cyclone Smooth parabolic arc (Gulf → landfall) 60 min 48 category, wind_speed_kph, radius_km, direction_deg
🌪 Tornado EF3 tornado Erratic jitter (random walk with drift) 5 min 36 intensity, speed_kph, direction_deg, width_m
🌊 Indian Ocean Tsunami tsunami Radial wave-front expansion from epicenter 15 min 16 wave_height_m, speed_kph, radius_km (growing)
🔥 California Wildfire wildfire Expanding radius (wind-driven perimeter growth) 30 min 24 intensity, radius_km (growing), acres_burned
🌧 Mississippi Flood flood Slow downstream drift + expanding inundation 60 min 24 intensity, radius_km (growing), water_level_m

Generator: services/database/seeds/004_trajectory_mock_data.py

A standalone Python script that:

  • Generates the 5 events above as CanonicalEvent objects with trajectory populated
  • Emits a ready-to-run 004_trajectory_mock_data.sql (INSERT statements)
  • Each path type has its own builder function (build_hurricane_path(), build_tornado_path(), etc.)
  • Path shapes are computed with simple math (sine curve for hurricane, random-walk for tornado, circular radius for tsunami/wildfire/flood)
  • current_index is set to ~50% through the path so the event looks "in progress" on the demo
